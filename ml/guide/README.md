# Cloud bucket + reference model trained on Microsoft GUIDE

Goal: tell, with a model trained on **real SOC labels**, whether an alert is a **true positive**, a **false positive**
or a **benign positive** — without putting any heavy computation or large dataset inside Sfumato.

```
Kaggle notebook (free)                           Google Cloud Storage bucket                 Sfumato (local, offline-capable)
GUIDE CSV ──► train_guide.py ──► signed model ──► gs://BUCKET/sfumato/guide_triage/<v>/ ──► downloads + verifies at start-up
HF dataset ─► build_kb.py ─────► signed KB    ──► gs://BUCKET/sfumato/sfumato_kb/<v>/   ──► pgvector (RAG for the AI report)
```

Sfumato never needs the dataset: only the small, signed artifacts. After the first download it runs offline.

## 1. Google Cloud (your 20 € budget)

Storage for these artifacts costs cents per month (a few hundred MB). **No GPU, no VM** is needed: the models are
gradient-boosted trees that train in minutes on CPU, and embeddings run on CPU.

**Shortcut (Windows):** after `gcloud auth login` and `gcloud config set project <ID>`, the script
`scripts/gcp_setup.ps1 -Bucket YOUR-BUCKET [-BillingAccount <ID>]` does steps 1-3 below and wires `.env`. It is
idempotent and never deletes anything. The manual commands follow for reference.

1. Console → *Billing → Budgets & alerts* → create a budget of **20 €** with alerts at 25 %, 50 % and 100 %.
2. Create the bucket (choose a us-central1 / us-east1 / us-west1 location: the Always Free storage allowance is
   documented for those regions — check Google's current free-tier page):
   ```bash
   gcloud storage buckets create gs://YOUR-BUCKET --location=us-central1 \
       --uniform-bucket-level-access --public-access-prevention
   ```
3. Two service accounts, least privilege, scoped to **this bucket only**:
   ```bash
   gcloud iam service-accounts create sfumato-trainer     # used by Kaggle: write
   gcloud iam service-accounts create sfumato-reader      # used by Sfumato: read-only
   PROJECT=$(gcloud config get-value project)
   gcloud storage buckets add-iam-policy-binding gs://YOUR-BUCKET \
       --member=serviceAccount:sfumato-trainer@$PROJECT.iam.gserviceaccount.com --role=roles/storage.objectAdmin
   gcloud storage buckets add-iam-policy-binding gs://YOUR-BUCKET \
       --member=serviceAccount:sfumato-reader@$PROJECT.iam.gserviceaccount.com --role=roles/storage.objectViewer
   gcloud iam service-accounts keys create trainer.json --iam-account=sfumato-trainer@$PROJECT.iam.gserviceaccount.com
   gcloud iam service-accounts keys create secrets/gcs-reader.json --iam-account=sfumato-reader@$PROJECT.iam.gserviceaccount.com
   ```
   Keep `trainer.json` out of the repository (paste it into the Kaggle secret, then delete it locally).

## 2. Train on Kaggle (free)

1. Open `sfumato_guide_kaggle.ipynb` on Kaggle (*File → Import notebook*).
2. *Add Input* → **Microsoft Security Incident Prediction** (the GUIDE dataset by Microsoft, CDLA-Permissive-2.0).
3. *Add-ons → Secrets*: `ARTIFACT_SIGNING_KEY` (same value as in Sfumato's `.env`, generated by `start.sh`/`start.ps1`)
   and `GCP_SA_JSON` (content of `trainer.json`). Internet on, accelerator **None**.
4. Edit `BUCKET_URI`, run all cells. A first run with `MAX_ROWS = 2_000_000` is a good smoke test.

The notebook is generated from the repository files (`python ml/guide/make_guide_notebook.py`): training code, shared
feature module and storage module are exactly what Sfumato uses.

## 3. Connect Sfumato

```
ML_ARTIFACT_URI=gs://YOUR-BUCKET/sfumato
KB_ARTIFACT_URI=gs://YOUR-BUCKET/sfumato      # after running sfumato_kb_kaggle.ipynb with BUCKET_URI set
GOOGLE_APPLICATION_CREDENTIALS=/run/secrets/gcs-reader.json
ARTIFACT_SIGNING_KEY=...                      # same value as the Kaggle secret
```
Restart, or call `POST /api/v1/ml/guide/sync` and `POST /api/v1/knowledge/sync`. Check `GET /api/v1/ml/guide`.

## What the model does — and does not

* Uses only **portable** GUIDE signals: alert category, MITRE ATT&CK techniques, entity types involved, hour/weekend.
  GUIDE's other columns are anonymised IDs (detector, device, alert title…) that no other system can reproduce.
* Metrics in `metrics.json` come from **organisations held out of training** (15 %), not from a random split, and
  include the binary view *threat (TP)* vs *non-threat (FP + BP)*.
* In an investigation it is a **second opinion capped at 10 points** of the threat score; it abstains when the alert
  maps onto no known category or technique, when the input is out of distribution, or when its confidence is low.
  A disagreement with the final verdict sends the incident to human review. It can never decide alone.
* GUIDE labels are analyst decisions of Microsoft customers, not ground truth, and alerts from other tools can be
  unlike them. The next step to improve it is retraining on your own analysts' verdicts.

## Security of the bucket

Models are pickles: loading one executes code. Therefore remote artifacts are only loaded if their **HMAC-SHA256
signature** (shared `ARTIFACT_SIGNING_KEY`) and every file's **sha256** verify. Someone who can write to the bucket
but does not know the signing key cannot get code executed by Sfumato. Sfumato's credentials are read-only.
